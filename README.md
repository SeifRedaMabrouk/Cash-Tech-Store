> **3.9:** النشر على Vercel + Neon موضح في `DEPLOY-VERCEL-NEON-AR.md` (قاعدة Postgres عبر `DATABASE_URL`، والأقسام اللي بتتكلم عن SQLite و`DATA_DIR` قديمة).

> قائمة التشغيل الفعلي خطوة بخطوة موجودة في `START-HERE-AR.md`.

المؤلف: user

موقع عربي RTL لعرض المنتجات والخدمات والسلة عبر واتساب. هذه الحزمة مستقلة عن Sites وChatGPT، ولا تحتاج حساب ChatGPT لتسجيل دخول المدير. لم يُنشر الموقع على أي استضافة.

## متطلبات الاستضافة

- Node.js 24 أو أحدث، مع إمكانية تشغيل خادم Node دائم.
- قرص دائم لحفظ مجلد البيانات والصور، وHTTPS على الدومين الحقيقي.
- لا تعمل وظائف الإدارة وقاعدة البيانات على استضافة ملفات ثابتة فقط أو استضافة PHP بدون Node.
- SQLite مناسبة لتشغيل نسخة واحدة من الخادم. لا تشغّل نسخًا متعددة موزعة على أقراص مختلفة. للتوسع لاحقًا يلزم ترحيل قاعدة البيانات إلى خدمة مشتركة.

## التشغيل

من مجلد المشروع:

```sh
npm install
npm run build
npm run admin:create
npm start
```

ستكتب كلمة مرور الإدارة في الطرفية بشكل مخفي، بطول ١٢ حرفًا على الأقل. اكتب بريد الدخول بنفسك: `npm run admin:create -- --email=بريد-خاص@example.com` واستخدم بريدًا مختلفًا عن بريد التواصل الظاهر في الموقع. لا توجد كلمة مرور جاهزة داخل المشروع.

افتح `http://127.0.0.1:3000` محليًا، ولوحة الإدارة `/admin`.

ملفات البناء جاهزة أيضًا في `dist/`. لتشغيلها مباشرة دون إعادة بناء:

```sh
npm install --omit=dev
npm run admin:create
npm start
```

## الإعدادات

انسخ `.env.example` إلى `.env`، ثم عدّل القيم. أو ضعها في إعدادات متغيرات بيئة الاستضافة.

- `APP_ORIGIN`: عنوان الموقع الكامل بدون مسار، مثال `https://your-domain.example`. **إجباري في الإنتاج** (`NODE_ENV=production`)؛ الخادم يرفض التشغيل بدونه. النسخة الأخرى من الدومين (www أو بدونها) تُحوَّل إليه تلقائيًا، وكذلك طلبات http عند ضبط `TRUST_PROXY`. لا يلزم دومين خارجي للاختبارات المحلية.
- `DATA_DIR`: مسار مجلد دائم؛ يحتفظ بقاعدة `cashtech.sqlite` والصور في `uploads/`.
- `HOST`: محليًا `127.0.0.1`؛ خلف خادم الاستضافة عادة `0.0.0.0`.
- `PORT`: المنفذ المطلوب من الاستضافة.
- `TRUST_PROXY`: عدد الـ reverse proxies الموثوقة أمام Node (الافتراضي `0`). خلف nginx أو Cloudflare أو منصة استضافة تضع بروكسي واحدًا اضبطه على `1`؛ عندها يُقرأ عنوان الزائر من آخر قيمة في `X-Forwarded-For` ويُحسب حد محاولات الدخول لكل زائر على حدة. لا ترفعه فوق عدد البروكسيات الفعلي لأن المهاجم قد يزوّر الهيدر.
- `SEED_DEMO=1`: لإنشاء منتجات تجريبية في قاعدة جديدة. الأفضل تعطيله بعد التجربة؛ توجد أيضًا إضافة أمثلة من لوحة الإدارة عندما يكون الكتالوج فارغًا.

لا ترفع `.env` أو مجلد البيانات إلى مستودع عام. خلف reverse proxy وجّه الطلبات إلى Node واضبط `APP_ORIGIN` على عنوان HTTPS الخارجي، واضبط `TRUST_PROXY=1` (أو عدد البروكسيات عندك). الخادم لا يثق بهوية مستخدم من هيدرات الطلب، ولا يقرأ `X-Forwarded-For` إلا بعد ضبط `TRUST_PROXY`.

## حساب الإدارة

لإنشاء حساب آخر من الطرفية فقط:

```sh
npm run admin:create -- --email=owner@example.com
```

لا يوجد تسجيل عام للحسابات. إعادة تعيين كلمة مرور حساب موجود:

```sh
npm run admin:create -- --email=بريد-الأدمن@example.com --reset
```

هذا يلغي جلساته الحالية. لا توجد استعادة كلمة مرور بالبريد أو خدمة إرسال بريد مجهزة؛ إعادة التعيين من الطرفية بواسطة صاحب صلاحية الخادم.

كلمات المرور مخزنة بتجزئة scrypt مع salt، والجلسات عشوائية مخزنة كتجزئة ولها صلاحية ٨ ساعات. ملفات Cookie محمية بـHttpOnly وSameSite=Strict وSecure عند HTTPS. توجد حماية من الطلبات الخارجية ومحاولات الدخول المتكررة، والتحقق من الصلاحيات على كل مسار إدارة.

حد محاولات الدخول (خلال ١٥ دقيقة): ١٠ محاولات فاشلة لكل عنوان + بريد، و٣٠ لكل عنوان. لا يوجد سقف عام على الحساب، فمهاجم يوزّع محاولاته على عناوين كثيرة لا يستطيع منع صاحب المحل من الدخول من عنوانه. يُفضّل أن يكون بريد دخول الإدارة (`admin:create --email=...`) مختلفًا عن البريد المعروض في صفحة "تواصل معنا". لو حُظر عنوانك بالخطأ فانتظر ١٥ دقيقة أو شغّل `npm run admin:unlock` على الخادم. لو ظهر في السجلات تحذير `TRUST_PROXY=0` فاضبطه على `1`.

## البيانات والخدمات

كل أسماء المنتجات وصورها وأسعارها ومواصفاتها والتوفر التجريبي موسومة بوضوح، ويجب استبدالها قبل التشغيل للعملاء. عبارات "نسخة تجريبية" و"صور توضيحية" تظهر في الموقع **فقط** عندما يوجد منتج موسوم "بيانات تجريبية"؛ فبمجرد حذف المنتجات التجريبية تختفي تلقائيًا. المنتج الجديد يُنشأ ظاهرًا ومتوفرًا وغير تجريبي، ويلزم رفع صورة له قبل الحفظ، وتُصغَّر الصور الكبيرة في المتصفح قبل الرفع (حتى ١٦٠٠ بكسل، WebP). معلومات المحل وروابطه وأسعار الخدمات مأخوذة من صاحب المحل.

عرض الافتتاح: من ٦ نوفمبر ٢٠٢٦ الساعة ٠٠:٠٠ إلى قبل ٩ نوفمبر ٢٠٢٦ الساعة ٠٠:٠٠ بتوقيت مصر. سحب المحافظ ٨ / ٩ جنيه لكل ألف، الإيداع ٠ / ٣، وInstaPay للسحب والإيداع ٣ / ٥. العمولة نسبية ثم تُقرّب لأعلى جنيه. السحب يعرض الصافي بعد خصمها، والإيداع يعرض الإجمالي بعد إضافتها.

السلة تراجع الأسعار والتوفر من الخادم قبل تكوين رسالة واتساب. الرسالة تُرسل بواسطة العميل بعد فتح واتساب، ولا يوجد دفع إلكتروني.

## الاختبارات

```sh
npm test
npm run typecheck
```

`npm test` يشغّل اختبارات التشغيل الأساسية (`portable.test.mjs`) واختبارات التقوية (`hardening.test.mjs`) واختبارات الإنتاج (`production.test.mjs`: الأرقام العربية، توقيت العرض، تحويل رقم الموبايل، روابط التواصل، تحويل www والشرطة الأخيرة، عناوين الصفحات للمشاركة، اسم المحل، ورسائل الأخطاء)، بالإضافة إلى: قفل الدخول، `TRUST_PROXY`، الأخطاء الشائعة في الطلبات، صفحات 404 وrobots وsitemap وgzip، تنظيف الصور غير المستخدمة، النسخ الاحتياطي، وتسجيل الأخطاء.

الاختبار المتكامل يشغّل خادمًا محليًا مؤقتًا وقاعدة منفصلة ثم ينظفهما. يفحص الدخول الصحيح والخاطئ، منع الزائر وتزوير الهيدرات، منع الطلب الخارجي، حفظ التعديلات وتعارض النسخ، الإخفاء، مراجعة السلة، رفع صورة وعرضها، رفض SVG، الحذف والخروج، حد محاولات الدخول، وتوقيت رسوم العرض والتقريب.

تم اختبار الواجهة السابقة على الكمبيوتر وعرض موبايل ٣٩٠ بكسل. نسخة الدخول المستقلة والتحويل إلى Node اختُبرا آليًا عبر HTTP محلي؛ لم يتم اختبارهما على دومين خارجي أو أجهزة فعلية. روابط واتساب فُحصت دون إرسال رسالة.

## Docker

ملف `Dockerfile` يبني الموقع من الكود مباشرة (لا يحتاج `dist` في GitHub) ويضبط `NODE_ENV=production` و`TRUST_PROXY=0` افتراضيًا (آمن). خلف بروكسي ومع قفل المنفذ 3000 عن الإنترنت مرّر `-e TRUST_PROXY=1`. مرّر `APP_ORIGIN` واربط `/app/data` بـ Volume دائم:

```sh
docker build -t cashtech .
docker run -d --restart unless-stopped -p 127.0.0.1:3000:3000 -e TRUST_PROXY=1 -e SEED_DEMO=0 -e APP_ORIGIN=https://your-domain.example -v cashtech-data:/app/data cashtech
# خلف بروكسي على نفس الجهاز: افتح المنفذ على 127.0.0.1 بس وفعّل الثقة في البروكسي
docker run -d --restart unless-stopped -p 127.0.0.1:3000:3000 -e TRUST_PROXY=1 -e APP_ORIGIN=https://your-domain.example -v cashtech-data:/app/data cashtech
docker exec -it <container> node server/create-admin.mjs
```

عند التشغيل يطبع الخادم العنوان ومسار البيانات، ويحذّر لو أُنشئت قاعدة بيانات جديدة فارغة (علامة أن القرص غير دائم) أو لو نسخة Node أقدم من المطلوب.

## النسخ الاحتياطي

النسخة الاحتياطية الآمنة تعمل والخادم شغال:

```sh
npm run backup
```

تنشئ مجلد `cashtech-<التاريخ>` داخل `DATA_DIR/backups` فيه قاعدة البيانات (نسخة متسقة) ومجلد الصور، وتحتفظ بآخر ١٤ نسخة (`--keep=30` لتغيير العدد، `--out=/مسار` لتغيير المكان). انسخ مجلد `backups` إلى مكان خارج الخادم دوريًا (مثلًا cron يوميًا). احتفظ أيضًا بملف `.env`. الطريقة اليدوية البديلة: أوقف الخادم وانسخ `DATA_DIR` كاملًا. لا تحذف قاعدة موجودة لإعادة تطبيق المخطط؛ النظام يطبّق مخططه الأول مرة واحدة ويحتفظ بالبيانات.

## المراقبة والتشغيل المستمر

- السجلات تُكتب على مخرجات الخادم (stdout/stderr): أي خطأ غير متوقع يظهر سطرًا بتاريخه ومسار الطلب. على Docker استخدم `docker logs`، وعلى PM2 استخدم `pm2 logs`.
- `GET /healthz` يعيد `{"ok":true}` عندما تعمل قاعدة البيانات، وصالح لمراقبة وقت التشغيل (UptimeRobot مثلًا). الـ Dockerfile فيه HEALTHCHECK جاهز.
- عند حدوث خطأ غير متوقع على مستوى العملية يسجّل الخادم الخطأ ثم يغلق نفسه، لذلك شغّله تحت مدير يعيد التشغيل: `docker run --restart unless-stopped` أو PM2 أو systemd بـ `Restart=always`.
- الصور المرفوعة التي لا يستخدمها أي منتج وعمرها أكثر من ٢٤ ساعة تُحذف تلقائيًا (عند التشغيل ثم كل ٦ ساعات).
- الموقع يقدّم `robots.txt` و`sitemap.xml` تلقائيًا من `APP_ORIGIN` والمنتجات الظاهرة. أضف الـ sitemap في Google Search Console بعد النشر.

## الباقي عند تشغيل استضافتك

ضبط الدومين وHTTPS والقرص الدائم، إنشاء كلمة مرور المدير، استبدال المنتجات التجريبية، وتجربة دخول ورفع صورة من جهازك. لا يحتاج المشروع إلى نشر اختبار على Sites أو موافقة/حساب من ChatGPT.

للتثبيت بإصدارات مقفولة عند استخدام pnpm: `pnpm install --frozen-lockfile` بدل `npm install`، ثم نفس أوامر البناء والتشغيل.
